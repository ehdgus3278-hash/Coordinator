# 단독 실행판 (Standalone)

폐쇄망(내부 네트워크)·오프라인 환경에서 **설치 없이** 시험해보기 위한 버전입니다.

## 사용법

1. `재활치료-코디네이터.html` 파일을 USB 등으로 병원 PC에 복사합니다.
2. 파일을 **더블클릭**합니다. (기본 브라우저에서 열립니다)
3. 끝. 인터넷, Node.js, Python 모두 필요 없습니다.

## 특징

- HTML 파일 1개로 완결 — 외부 라이브러리·CDN·서버 의존성 없음
- 백엔드(`backend/app/scheduler/engine.py`)의 스케줄링 엔진을 JavaScript로 그대로 포팅
  - 우선순위 1: 동일 치료실 묶기
  - 우선순위 2: 이동 최소화
  - 우선순위 3: 전체 가능 시간대에 걸쳐 가장 한산한 슬롯에 배정하는 로드밸런싱(특정 시간대에 몰리지 않고 골고루 분산)
  - 우선순위 4: 치료실/스테이션 수용 초과 시 자동으로 다음 슬롯 배정
- 뇌재활치료실은 명명된 스테이션(M1~M4, B1~B2, T1~T3, 담당 치료사 4인) 구조를 그대로 반영
  - 처방코드별로 배정 가능한 구역(zone)이 제한됩니다 (예: MM10204 는 T구역만)
  - "1:1치료실"은 별도 방이 아니라 뇌재활치료실 내 치료사별 전담 시간(THERAPIST구역)을 의미하며,
    담당 치료사 4인이 있어도 한 타임 최대 2명까지만 배정됩니다
  - MM151AM/PM 같은 중첩 사용 코드는 대상 코드(MM301AM/PM, MM302AM/PM)와 같은 슬롯·스테이션을 공유합니다
  - 환자 이름 옆에 표시되는 라벨(예: 홍길동1(301AM), 홍길동1F(301AM+151AM), 홍길동M(102), 홍길동T(10204))도 동일하게 계산됩니다
- MM301/MM302/MM151/MM105는 오전(AM)/오후(PM) 코드로 분리되어 있습니다
  (예: MM301AM/MM301PM) — AM 코드는 08:00~11:30, PM 코드는 13:30~16:30 슬롯에만 배정됩니다
- 분배를 위한 "한 타임당 최대 인원" 제한이 물리적 스테이션 수와 별도로 적용됩니다
  (M구역 3명/B구역 1명/T구역 2명/THERAPIST구역 2명, 작업·언어치료실 각 2명) — 한도에 도달하면 같은 슬롯의
  다른 구역/치료실로, 그래도 없으면 가장 한산한 다음 시간대로 자동 분산됩니다
- 입력한 데이터는 그 브라우저의 `localStorage`에 저장됩니다 (새로고침해도 유지)

## 한계 (정식판과의 차이)

| 항목 | 단독 실행판 | 정식판 (backend + frontend) |
|---|---|---|
| 설치 | 불필요 | Python·Node 필요 |
| 데이터 저장 | 브라우저 1대에만 | 공용 DB(PostgreSQL 등) |
| 여러 PC 공유 | ❌ | ✅ |
| 치료사별 시간표 | (생략) | ✅ |

> 단독 실행판은 **시연·기능 검증용**입니다. 여러 직원이 동시에 같은 데이터를 보려면
> 정식판을 사내 서버에 배포해야 합니다.
